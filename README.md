## 📊 PHASE 1. LLM 모델 비교·선정 보고서

### 1.1 비교 목적 및 대상 모델
- **목적**: 동일한 과업(프롬프트 엔지니어링 과제 가이드라인 분석 및 템플릿 도출)을 최신 4종의 대규모 언어 모델(LLM)에 주입하여, 구조화 능력, 예시 생성 품질, 가독성을 정량적·정성적으로 비교하고 최적의 모델을 선정합니다.
- **실험 환경 및 대상 모델**:
  - **ChatGPT (GPT-4o / v5.5)**: 유료 Plus 플랜 / 웹 인터페이스 / 2026-06-04 테스트 수행 (Temperature: default)
  - **Claude 3.5 Sonnet (v4.6)**: 유료 Pro 플랜 / 웹 인터페이스 / 2026-06-04 테스트 수행 (Temperature: default)
  - **Grok 4.3 Fast**: 유료 Premium 플랜 / 웹 인터페이스 / 2026-06-04 테스트 수행 (Temperature: default)
  - **Gemini 3.5 Flash**: 무료 플랜 / 웹 인터페이스 / 2026-06-04 테스트 수행 (*무료 버전 특성상 복잡한 추론 및 토큰 제한으로 밀도가 다소 낮음*)

### 1.2 정량적 평가 기준 및 점수표
5점 척도(1: 불량, 2: 미흡, 3: 보통, 4: 우수, 5: 탁월)를 기준으로 평가 축을 구성하여 심사하였습니다.

| 평가 항목 (Evaluation Pillars) | ChatGPT (5.5) | Claude (4.6) | Grok (4.3) | Gemini (3.5) |
| :--- | :---: | :---: | :---: | :---: |
| **① 구조화 및 가독성 (Markdown)** | 5 | 5 | 5 | 4 |
| **② 핵심 개념 전달력 (이론 요약)** | 4 | 5 | 4 | 4 |
| **③ 실전 가이드 구체성 (실무 연계)** | 5 | 4 | 4 | 4 |

| **⑤ 과제 적합성 (학습 목표 달성도)** | 4 | 5 | 5 | 5 |

### 1.3 모델별 정성 평가 및 요약

#### 🥇 공동 1위: ChatGPT (GPT-4o) - 실전 및 데이터 특화 (23점)
- **장점**: 프롬프트 패키지에 포함되어야 할 실전 데이터를 가장 구체적이고 풍부하게 구현했습니다. Few-shot 예시 3개(정상 2개, 모호 1개), 환각 검증 테이블 5개 등 즉시 활용 가능한 데이터 세트를 텍스트로 명확히 뽑아내는 능력이 탁월합니다.
- **단점**: LLM의 동작 원리(확률적 예측)에 대한 이론적 깊이가 다른 상위 모델에 비해 직관적이고 단순하게 서술되었습니다.

#### 🥇 공동 1위: Claude 3.5 Sonnet - 구조화 및 인사이트 특화 (23점)
- **장점**: 학습 목표와 핵심 개념을 가장 완벽하게 요약했습니다. Zero-shot, Few-shot, CoT 기법의 아키텍처 차이를 코드 블록과 다이어그램 형태로 시각화하여 가독성이 매우 뛰어나며, 문서의 논리적 흐름이 완벽합니다.
- **단점**: 구현된 입력 템플릿 및 Few-shot 샘플 데이터의 절대적인 분량이 ChatGPT에 비해 다소 간결하게 정리되어 있습니다.

#### 🥉 3위: Grok 4.3 Fast - 레이아웃 및 뼈대 구축 우수 (20점)
- **장점**: 프레임워크를 표(Table) 형태로 요약하는 능력이 우수하며 시원시원한 톤앤매너를 가집니다. 프로젝트 초기 뼈대를 설계하는 단계에서 매우 유용합니다.
- **단점**: 뒤로 갈수록 구체적인 세부 예시나 환각 검증 질문 리스트의 디테일이 부족하고 개요 수준에 머무르는 아쉬움이 있습니다.

#### ⑭ 4위: Gemini 3.5 Flash - 친절한 멘토링 및 비즈니스 관점 (19점)
- **장점**: "기업 환경에서 AI를 신뢰할 수 있는 파트너로 검증하는 프로세스"라는 비즈니스 관점의 해석이 훌륭하며, 톤앤매너가 가장 친절하고 부드럽습니다.
- **단점**: 텍스트(줄글) 중심의 서술이 많아 한눈에 구조를 스캔하기 어렵고, 코드 블록이나 테이블의 밀도가 낮아 개발 및 아키텍처 문서로는 가독성이 떨어집니다.

### 1.4 최종 선정 결론
> **"본 프로젝트의 메인 엔진으로 'Claude 3.5 Sonnet'을 채택하며, 실전 Few-shot 데이터셋 구축에는 'ChatGPT'를 하이브리드로 벤치마킹한다."**
> 
> **선정 근거 3줄 요약**:
> 1. 업무 자동화 프롬프트 패키지는 다턴(Multi-turn) 대화에서의 문맥 유지와 철저한 형식 준수가 핵심이므로, 해당 지표에서 가장 안정적인 가독성을 보여준 Claude를 기본 모델로 채택함.
> 2. 다만, 실제 프롬프트 내부에 주입할 구체적인 예시 데이터와 환각 검증 시나리오 셋을 확보할 때는 ChatGPT가 생성한 세부 템플릿 소스를 결합하는 하이브리드 전략이 가장 효과적임.
> 3. Gemini와 Grok은 보조 아이디어 브레인스토밍 툴로 활용하여 파이프라인을 보완함.

## ☑️ 과제 완료 체크리스트 (Master Checklist)

### 1. 모델 비교 및 선정 보고서 섹션

* [x] 서로 다른 3개 이상의 LLM 선정 및 동일 과업 투입
* [x] 사용 환경(웹/앱/API) 및 요금제, 주요 설정 명시
* [x] 최소 4개 이상의 평가 축 기준 수립 및 점수 부여
* [x] 최종 모델 선정을 위한 3줄 이상의 명확한 근거 작성

### 2. 시스템 설계 문서 섹션

* [ ] 타겟 사용자, 입력 데이터 형태, 출력 규격 정의
* [ ] 재사용성 높은 '입력 템플릿' 1개 이상 제시
* [ ] 구체적인 페르소나(직무, 말투, 금지사항, 우선순위) 선언
* [ ] 안전장치(모르면 모른다고 하기, 확인 질문하기)가 포함된 시스템 프롬프트 설계
* [ ] Few-shot 예시 3개 이상 포함 (그 중 1개는 모호한 입력에 대한 AI의 되묻기 포함)
* [ ] 일반 지시(v1)와 단계적 추론 유도(v2) 프롬프트 전/후 비교 및 최종 답변 요약화 규칙 적용

### 3. 환각(Hallucination) 검증 섹션

* [ ] 사실 기반 검증 질문 5개 이상 준비
* [ ] 각 질문별 기대 정답, 허용 오차, 참고 근거 작성
* [ ] Pass(정답 또는 모른다고 답함) / Fail(확신하며 틀린 정보 제공) 판정 기준 수립

### 4. 실행 로그 및 문맥 유지 검증 섹션

* [ ] 선택한 과업 시나리오로 실제 10턴 이상 대화 수행 및 전문 기록
* [ ] 대화 중간에 조건 변경(톤/대상 변경) 또는 추가 정보 뒤늦게 제공하는 상황 연출
* [ ] 10턴 내내 이전 요구사항이 훼손되지 않고 일관되게 유지되는지 검증
* [ ] 대화 로그를 가독성 좋게 섹션/번호/요약 추가하여 편집 정리
