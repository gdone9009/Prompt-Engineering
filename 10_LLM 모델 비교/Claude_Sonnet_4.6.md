## 🧠 먼저 알아야 할 핵심 개념

### 1. LLM이란 무엇인가?
AI는 "정답을 아는 것"이 아니라 **"다음에 올 확률이 높은 단어를 생성"** 합니다. 그래서 그럴듯하지만 틀린 말을 자신 있게 하는 **환각(Hallucination)** 이 생깁니다.

### 2. 프롬프트 기법 3가지

```
Zero-shot:  "이 이메일 요약해줘"
            → 예시 없이 바로 요청

Few-shot:   "예시1: 입력A → 출력A
             예시2: 입력B → 출력B
             이제 이걸 해줘"
            → 좋은 예시 3개 이상을 먼저 보여줌

단계적 추론: "먼저 요구사항을 정리하고,
              빠진 정보가 있으면 질문하고,
              그 다음에 초안을 작성해줘"
            → 생각하는 순서를 지정해줌
```

### 3. 시스템 프롬프트란?
대화 시작 전에 AI에게 주는 **"역할 지침서"** 입니다.

```
예시:
당신은 10년 경력의 프로젝트 매니저입니다.
- 답변은 항상 불릿 형식으로 작성하세요
- 수치/정책은 근거 없이 단정하지 마세요
- 정보가 부족하면 최대 3개까지 질문하세요
```

## 🛠️ 수행 순서 (Step by Step)

### STEP 1 | 업무 과제 하나 선택 (10분)

아래 중 하나를 고르세요. 가장 쉬운 건 **회의록 요약**입니다.

- 📧 이메일 초안 작성
- 📝 회의록 요약 ← **추천 (예시 많음)**
- 📊 보고서 개요 생성
- ✅ 요구사항 정리

---

### STEP 2 | 모델 3개 비교하기 (1~2시간)

**사용할 AI 3개:**
- ChatGPT (gpt.com 무료/유료)
- Claude (claude.ai) ← 지금 대화 중인 저입니다
- Gemini (gemini.google.com)

**방법:**
1. 동일한 입력(예: 샘플 회의록)을 3곳에 똑같이 붙여넣기
2. 결과를 아래 표로 비교

| 평가 축 | ChatGPT | Claude | Gemini |
|--------|---------|--------|--------|
| 정확성 (1~5) | | | |
| 한국어 자연스러움 | | | |
| 형식 준수 | | | |
| 긴 문맥 유지 | | | |
| 속도/안정성 | | | |
| 비용 | | | |

---

### STEP 3 | 시스템 프롬프트 설계 (1시간)

**v1 (나쁜 예):**
```
회의록을 요약해줘.
```

**v2 (좋은 예):**
```
당신은 꼼꼼한 PM 출신 업무 자동화 도우미입니다.

[역할] 회의록을 구조화된 형식으로 요약
[출력 형식]
- 결정사항: (번호 목록)
- Action Items: 담당자 | 내용 | 기한
- 확인 필요: (근거가 없는 항목)

[규칙]
- 수치나 정책은 확인 없이 단정하지 않는다
- 정보가 부족하면 최대 3개 질문 후 시작
- 추측성 표현 금지
```

---

### STEP 4 | Few-shot 예시 3개 작성 (30분)

| 번호 | 특징 | 내용 |
|------|------|------|
| 예시 1 | 정상 입력 | 충분한 회의록 → 깔끔한 요약 |
| 예시 2 | 정상 입력 | 다른 주제 → 다른 형식 요약 |
| 예시 3 | **모호한 입력** | 정보 부족 → AI가 질문을 되묻는 예시 |

예시 3이 핵심입니다. AI가 "이 부분은 불확실합니다. 확인해주세요"라고 하는 케이스를 보여줘야 합니다.

---

### STEP 5 | 환각 검증 (30분)

검증 가능한 질문 5개를 준비합니다.

```
예시 질문들:
Q1. 한국 근로기준법에서 연차 발생 기준은?
Q2. 2024년 최저임금은 얼마인가?
Q3. (당신 회사의) 출장비 정산 규정 예외 조건은?
```

판정 기준:
- ✅ **Pass**: 정답을 말하고 근거 제시 OR "모른다/확인 필요"라고 명시
- ❌ **Fail**: 틀린 정보를 근거 없이 자신 있게 말함

---

### STEP 6 | 10턴 대화 로그 수집 (1시간)

대화 중 **반드시 포함할 상황:**
- 중간에 조건 변경: *"톤을 더 공식적으로 바꿔줘"*
- 정보 추가 제공: *"아, 그리고 이 회의에 임원이 참석했어"*

AI가 이전 맥락을 유지하면서 변경사항만 반영하는지 확인합니다.

## 💡 핵심 팁

> **이 과제의 진짜 목적은 "AI를 잘 쓰는 것"이 아니라 "AI를 체계적으로 평가하고 개선하는 사람"이 되는 것입니다.**

"느낌"으로 평가하지 말고, 항상 **근거와 기준**을 세우는 습관을 만드는 게 이 과제의 핵심입니다.
